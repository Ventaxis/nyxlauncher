# Архитектура NyxLauncher

Документ описывает устройство приложения, потоки данных и принятые решения.
Версия 0.4.0.

## 1. Общая схема

```text
┌──────────────────────────────────────────────────────────────┐
│ WebView2 (React 19 + Vite)                                   │
│   ui/src/App.jsx          состояние экранов и обработчики     │
│   ui/src/api.js           обёртки invoke + демо-режим         │
│   ui/src/components/      Shelf, Detail, Settings, History     │
└───────────────────────────┬──────────────────────────────────┘
                            │ Tauri IPC (invoke)
┌───────────────────────────▼──────────────────────────────────┐
│ Rust-ядро (src-tauri)                                        │
│   lib.rs        AppState, команды, трекер, трей, автозапуск   │
│   engine.rs     статистика и достижения (чистые функции)      │
│   integrity.rs  HMAC-конверт, загрузка и запись подписанных   │
│   settings.rs   модель настроек, HKCU\...\Run                 │
│   winutil.rs    проверка exe, видимое окно, иконки           │
│   store.rs      атомарная запись JSON                         │
└───────────────────────────┬──────────────────────────────────┘
                            │
              %APPDATA%\corp.ventaxis.nyxlauncher
```

Сетевого слоя нет: приложение не содержит HTTP-клиента и не инициирует
соединений.

## 2. Состояние

`AppState` в `lib.rs` держит:

| Поле | Назначение |
| --- | --- |
| `write_lock` | сериализует запись файлов |
| `games`, `sessions`, `unlocked` | библиотека, сессии, открытые достижения |
| `active` | текущие сессии: игра → монотонная метка старта |
| `launched` | PID, порождённые лаунчером |
| `icons` | кэш data-URL иконок |
| `settings` | настройки в памяти |
| `meta` | идентификатор установки, `last_seen` |
| `tampered`, `clock_rollback` | флаги предупреждений |

**Порядок блокировок:** `write_lock → games → sessions → active → unlocked`,
затем `launched`, `icons`, `settings`. Обратный порядок запрещён — это
предотвращает дедлок.

## 3. Трекер

Фоновый поток с интервалом `settings.poll_secs`:

1. получает снимок процессов через `sysinfo`;
2. сопоставляет пути с библиотекой;
3. применяет фильтры: минимальная сессия, видимое окно, строгий режим;
4. открывает и закрывает сессии, обновляя `active`;
5. пересчитывает достижения и сохраняет изменения.

Длительность считается по `Instant`, поэтому перевод системных часов не
меняет результат. `meta.last_seen` дополнительно выявляет откат часов более
чем на 300 секунд.

## 4. Целостность данных

Файл состояния хранится в конверте:

```json
{ "v": 1, "sig": "<base64 HMAC-SHA256>", "data": { ... } }
```

Перед подписью и проверкой объект приводится к канонической форме:
ключи объектов рекурсивно сортируются. Это исключает ложные срабатывания при
изменении порядка ключей сериализатором.

Ключ — 32 случайных байта из `getrandom`, файл `secret.bin` с правами
текущего пользователя. При несовпадении подписи файл переименовывается в
`*.tampered.bak`, в интерфейсе появляется предупреждение, состояние
загружается из резервной копии или значения по умолчанию.

Старые файлы без конверта читаются как обычный JSON и при следующей записи
переводятся в подписанный формат.

## 5. Проверка исполняемых файлов

`winutil.rs` при добавлении игры:

1. отклоняет файлы вне `.exe` и внутри `%WINDIR%`;
2. проверяет сигнатуру `MZ` и PE-заголовок;
3. требует размер не меньше 16 КБ;
4. отклоняет имена системных и служебных утилит и сам лаунчер;
5. считает SHA-256 и сохраняет его в записи игры.

В строгом режиме сессия засчитывается только при совпадении хеша, наличии
видимого окна с непустым заголовком и PID из списка `launched`.

## 6. Иконки

`SHGetFileInfoW` с `SHGFI_SYSICONINDEX` даёт системный индекс иконки;
`SHGetImageList` (JUMBO, при неудаче — EXTRALARGE) и `IImageList::GetIcon`
возвращают `HICON`; `GetIconInfo` и `GetDIBits` — пиксели; `png` кодирует
изображение, результат кэшируется в `icons/<id>.png` и в памяти как data-URL.
При недоступности системного списка используется `ExtractIconExW`.

## 7. Интерфейс

- Один экран-состояние: `library`, `detail`, `settings`.
- `api.js` изолирует IPC: вне Tauri те же функции работают с демо-библиотекой,
  что позволяет проверять интерфейс в обычном браузере.
- Настройки сохраняются с задержкой 350 мс после последнего изменения.
- Тёмная тема — единственная базовая; варианты различаются палитрой.
- Анимации отключаются системной настройкой `prefers-reduced-motion` и
  переключателем в интерфейсе.

## 8. Сборка и релиз

`npm run build` собирает `ui/dist`, который встраивается в бинарник.
`npx tauri build` создаёт exe и NSIS-установщик. CI на каждый пуш в `main`
прогоняет 35 тестов и собирает артефакты; тег `v*` публикует релиз с
установщиком, переносным exe и контрольными суммами.

## 9. Ограничения

- Только Windows 10/11 x64: Win32 API, реестр, WebView2.
- Учёт времени локален по своей природе и не является защищённой метрикой.
- Приложение не работает с играми, требующими собственного лаунчера с
  проверкой целостности файлов, если запуск выполняется в обход него.
