# Участие в разработке

Спасибо за интерес к NyxLauncher. Ниже — правила, которые делают участие
предсказуемым и юридически чистым.

## 1. Перед началом

- Ошибки и предложения обсуждаются в разделе Issues.
- Крупные изменения (архитектура, новые экраны, форматы данных) сначала
  согласуются в issue, чтобы не переписывать работу дважды.
- Уязвимости не обсуждаются публично — см. [SECURITY.md](SECURITY.md).

## 2. Требования к среде

| Инструмент | Версия |
| --- | --- |
| Windows | 10 или 11, x64 |
| Node.js | 22 или новее |
| Rust | stable, MSVC toolchain |
| Visual Studio Build Tools | «Разработка классических приложений на C++» |
| WebView2 Runtime | установлен в системе |

```powershell
npm ci
npm run build          # фронтенд в ui/dist
cargo test --manifest-path src-tauri/Cargo.toml
npx tauri build        # exe + NSIS-установщик
```

## 3. Правила кода

- **Язык.** Комментарии, тексты интерфейса и сообщения об ошибках — на русском.
  Идентификаторы кода — на английском.
- **Стиль Rust.** `cargo fmt` перед коммитом; предупреждения `cargo clippy`
  не игнорируются.
- **Стиль JS.** 2 пробела, одинарные кавычки, точки с запятой, функциональные
  компоненты React.
- **Логика — в движке.** Расчёты статистики и достижений живут в `engine.rs` и
  покрываются тестами без обращения к файловой системе и процессам.
- **Настройка обязана работать.** Запрещено добавлять переключатели и пункты
  меню, которые ничего не меняют в поведении.
- **Данные — только через подпись.** Любая запись в `games.json`,
  `sessions.json`, `achievements.json`, `settings.json` и `meta.json` идёт через
  `integrity.rs`.
- **Порядок блокировок.** `write_lock → games → sessions → active → unlocked`,
  далее `launched`, `icons`, `settings`. Нарушение порядка ведёт к дедлоку.
- **Никаких сетевых вызовов.** Приложение остаётся полностью локальным.

## 4. Тесты

Изменение поведения сопровождается тестом. Минимум перед отправкой:

```powershell
cargo test --manifest-path src-tauri/Cargo.toml
npm run build
```

Тесты должны быть детерминированными: без обращения к реальному реестру,
реальным играм и сети.

## 5. Коммиты и пул-реквесты

- Сообщение коммита — на русском, в формате `область: краткое описание`.
- Один пул-реквест — одна задача. Смешанные изменения сложнее проверять.
- В описании PR укажите: что изменено, зачем, как проверено.
- Интерфейсные изменения сопровождаются скриншотом до/после.
- Ветка создаётся от `main`; перед отправкой выполните rebase.

## 6. Лицензия на вклад

Отправляя пул-реквест, вы подтверждаете, что:

1. являетесь автором изменений или имеете право их передать;
2. предоставляете Ventaxis Corp бессрочную, неисключительную, безотзывную,
   всемирную, безвозмездную лицензию с правом сублицензирования на
   использование, воспроизведение, изменение, распространение и включение
   вашего вклада в состав NyxLauncher в любой форме;
3. гарантируете, что вклад не нарушает права третьих лиц;
4. понимаете, что вклад может быть отклонён или изменён без объяснения причин.

Вклад не даёт прав на товарные знаки проекта и не делает вас соавтором
продукта в юридическом смысле.
